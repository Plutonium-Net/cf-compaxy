# CF-Compaxy

Compaxy on Cloudflare Workers: three proxy engines behind one origin, with the
Wisp transport served from the same Worker.

Credit:
MercuryWorkshop/wisp-server-workers: INSPIRED Wisp protocol on Cloudflare Workers.
Obviously Mercury Workshop for Wisp
Titanium Network for SJ v2 and UV
The (second) sexiest agentic AI Freebuff.

```text
iframe / browser  ->  this Worker  ->  one of three engines  ->  upstream site
   ?url=...            routing table
```

| Engine | How it proxies | Needs |
| --- | --- | --- |
| `base` | fetches, rewrites and re-emits pages server-side | nothing |
| `scramjet` | Scramjet v2 in a service worker, frames driven by its controller | Wisp, https origin |
| `ultraviolet` | Ultraviolet 3 in a service worker | Wisp, https origin |

There is no Rammerhead and no fourth engine. Unlike the Node build, there is no
separate Wisp deployment to run: `src/wisp/` is the transport, mounted on the
same origin at `/wisp/<engine>/`.

## Run it

```bash
npm install
npm run dev        # http://127.0.0.1:8787
npm run deploy     # wrangler deploy
node test/wisp-spike.mjs ws://127.0.0.1:8787/wisp/scram/   # transport smoke test
```

## Routes

| Route | Serves |
| --- | --- |
| `/?url=<address>` | entry point; redirects to the engine that owns the site |
| `/proxy/<scheme>/<host>/<path>` | base engine: the mirrored target path |
| `/scram/` | Scramjet v2 frame host; proxied pages under `/scram/<frame>/<url>` |
| `/uv/service/` | Ultraviolet proxied pages |
| `/go/scramjet`, `/go/ultraviolet` | bootstrappers |
| `/wisp/scram/`, `/wisp/uv/` | Wisp v1/v2 WebSocket endpoints |
| `/healthz`, `/blocked-hosts.json` | status and blocklist rules |

Engine code is static assets under `public/`, served by name only: `/sj/`
(Scramjet bundle, wasm, controller), `/uv/` (Ultraviolet), `/baremux/`,
`/epoxy/` (Ultraviolet's transport), `/epoxy3/` (Scramjet's transport). The
workers and configs at `/scram/sw.js`, `/uv/sw.js` and `/uv/uv.config.js` are
generated by the Worker so their prefixes always match the routes it serves.

## Routing table

`src/sites.json` decides which engine serves which site, and is bundled at deploy
time. Same rules as the Node build: a bare host matches the domain and every
subdomain, `*.example.com` matches subdomains only, entries are tried in order,
and unlisted sites use `default`.

## The Wisp transport

`src/wisp/` is `@mercuryworkshop/wisp-js` (LGPL-3.0, licence included) minus its
Node glue. Two files are ours:

- `src/wisp/compat.mjs` — Workers globals instead of `node:net`/`node:dgram`.
- `src/wisp/server/net.mjs` — the socket layer, on `cloudflare:sockets`.

Everything else — packet encoding, extensions, the v1/v2 handshake, flow control,
stream filters — is upstream code, unmodified. `src/wisp/index.js` is the
replacement for upstream's `server/http.mjs`: it answers an upgrade with a
`WebSocketPair`, hands the socket to `ServerConnection`, and keeps it alive with
`ctx.waitUntil`.

new version of the package and re-link the two files above.

### Caps and what they mean

- **Six open sockets per session, and the rest queue.** The budget is per
  session, not per isolate: each visitor gets its own six, so one page pinning
  every slot cannot stall anyone else. Workers allow six
  simultaneous outbound connections per request, and a Wisp session is one
  request. Refusing the seventh reaches the browser as a TLS failure in the
  middle of a handshake, so `src/wisp/server/net.mjs` holds a six-slot semaphore
  instead and the excess waits: a page asking for 200 subresources loads
  six-at-a-time instead of losing most of them. There is no slot deadline: a stream waits as long
  as it takes, and is dropped from the queue when the browser abandons its
  request, so waiting never turns into a failure. `/healthz` reports
  `transport.scope`, `transport.sessions`, and the summed
  `transport.active` / `transport.waiting`.
- **TCP only.** `connect()` has no UDP, so the UDP extension is not advertised
  and a client that asks for one is refused.
- **Private and loopback ranges are refused**, and the blocklist is wired into
  the transport's `hostname_blacklist`, so a blocked site dies at the socket
  rather than only inside the engine.

## Behaviour differences from the Node build

- **No DNS-based SSRF check.** Workers has no resolver API. Literal private
  addresses and reserved hostnames are refused by `src/urls.js`; Cloudflare's
  egress refuses private destinations for `fetch` and `connect()`.
- **The response cache is per isolate.** `src/cache.js` is unchanged, so it is
  fast but not shared: a cold isolate starts empty. The Cache API is the natural
  upgrade if cross-isolate reuse matters.
- **WebSocket relay is message-based.** The Node build piped bytes; here the two
  sockets are bridged with `fetch(..., { Upgrade: "websocket" })` and
  `message` events. A refusal from upstream answers `502` instead of relaying the
  plain HTTP response.
- **CPU and memory are per request** (30 s CPU on Workers Paid). Rewriting a very
  large document is the only place that matters.

## Verified

Run against `wrangler dev` on this machine:

- **Wisp transport**: wisp-js client, v2 handshake negotiated, one TCP stream to
  `example.com:80`, `HTTP/1.1 200` and 931 bytes returned through
  `cloudflare:sockets`; a stream to `127.0.0.1:80` refused with close reason 72.
- **base engine**: `/proxy/https/example.com/` returns the rewritten document
  (`text/html`, shim injected); `/proxy/wss/ws.postman-echo.com/raw` relays a
  message out and back.
- **assets**: `/sj/scramjet.js`, `/sj/scramjet.wasm` (`application/wasm`),
  `/uv/uv.bundle.js`, `/baremux/`, `/epoxy/`, `/epoxy3/` and the brand PNGs all
  serve with correct content types.
- **routing and surfaces**: `/?url=` redirects to the engine that owns the site;
  `/scram/`, `/scram/sw.js`, `/uv/sw.js`, `/uv/uv.config.js` and both
  bootstrappers answer `200`.

- **both service-worker engines, in a browser**: Scramjet v2 registered
  `/scram/sw.js`, loaded `scramjet.wasm` and its controller, and served
  `https://example.com/` at `/scram/<frame>/<codec>/https%3A%2F%2Fexample.com%2F`;
  Ultraviolet registered `/uv/sw.js` and served the same site at
  `/uv/service/...`. Both reached the site through this Worker's own Wisp
  endpoint.

Not verified: the same two engines on a deployed origin (only `wrangler dev` on
`127.0.0.1` was exercised).

## Security

Do not expose this unauthenticated on the internet. There is no password gate:
put authentication in front of it, or keep it private. Private networks are
refused as described above.
